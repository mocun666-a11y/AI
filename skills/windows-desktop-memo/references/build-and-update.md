# 构建与更新

## 新工程

读取项目约定并检查运行环境。用脚手架创建新目录，选择独立应用标识和可用热键；不要覆盖非空目录。建立工程虚拟环境，安装生成的 `requirements.txt`，若版本不兼容则选择适用版本重新验证，不盲目改系统 Python。

在工程目录运行 `python -m unittest test_memo -v`。模板测试不写正式数据、不注册全局热键。调试时检查最小尺寸、长文字、多任务、月份边界及背景。

## 打包

以下示例按实际路径替换；分别执行并检查退出状态：

```powershell
& <venv-python> -c "from app import icon_image; icon_image().save('memo.ico', sizes=[(16,16),(32,32),(48,48),(64,64)])"
& <venv-python> -m PyInstaller --noconfirm --windowed --onedir --name <应用名> --icon memo.ico --collect-submodules pystray app.py
```

`--onedir` 产物包含 exe 和依赖目录，部署完整产物，不能默认只换 exe 即包含依赖变化；不要依赖开发环境才能运行。

模板有 `--smoke-test <报告路径>`：使用临时数据，会短暂显示测试窗口和托盘。先确认热键未被正式实例占用，或为测试工程指定独立热键；不能为了测试关闭不相关软件。

## 验证层次

| 层次 | 验证 |
| --- | --- |
| 数据 | 中文和完成状态重开、日期隔离、无效输入、备份恢复、保存失败保护 |
| 状态 | 穿透和不抢焦点、编辑控件、托盘、重复启动、热键冲突替代入口 |
| 外观 | 实时预览、取消不保存、保存重开、最小尺寸、临时编辑放大 |
| 背景 | 图片确实可见、裁切缩放、取消恢复、保存副本、原图移动、纯色恢复 |
| 打包 | 打包程序的核心场景与报告，Tcl/Tk 和图片插件可用 |
| 安装 | 真实快捷方式、预期实例、新版文件、托盘退出和用户数据 |

几何或样式检查不替代目视验收。用当前环境允许的界面工具；截图捕获超时须保留待验证项，不能把“没有报错”当作“外观正确”。

## 更新已有安装

1. 确认运行文件完整路径、源码、数据目录及未保存输入/预览。优先用应用退出流程保存退出，不按通用进程名批量终止。不能确认未保存内容时先保护或让用户保存。
2. 备份数据与旧安装，记录数据摘要；先在独立产物目录构建和检查，再替换正式安装。安装与备份路径分开，不递归删除未经核实的计算路径。
3. 保持应用标识，不覆盖用户数据，不把测试任务或样例壁纸带入正式数据。
4. 启动新版，验证文件及关键行为、日志和任务保留。数据格式迁移会改变文件摘要，此时比较任务及设置的语义。
5. 检查失败恢复旧安装并保留数据；停止无变化的重复尝试，按具体错误处理。权限阻塞无法解决时说明阻塞点。

登录启动默认关闭。快捷方式与安装位置按本机解析，不硬编码开发者用户名。
