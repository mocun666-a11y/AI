# 归档与发布

## Obsidian：仅在已授权时

读选定知识库的规则、索引及工具笔记。追问更新同一工具笔记，保留手工内容；当前说明与历史更新分开，过时说明标明替代关系。

记录需求、入口、状态切换、外观背景、数据位置、验证范围、限制和交付文件。快捷键、菜单路径用表格注明系统和软件。工具开发不计为用户错题，不创建定时任务。

写入后回读，再给链接；按知识库规则更新索引和日志。知识库路径属于会话配置，不进入公共模板；未授权归档时不强求连接 Obsidian。

## GitHub：当前请求包含上传时

确认连接账号、目标仓库、默认分支、写权限与仓库约定。优先用合适的现有仓库；目标无法合理确定时只询问目标，不重复索取已授予的上传授权。

发布用白名单：SKILL.md、agents 元数据、必要 references/scripts、通用模板源码及测试。不要递归上传整个工程，排除用户计划、数据备份、壁纸、知识库原文、虚拟环境、运行日志、机器路径、检查报告、旧版 exe、密钥及凭据。

先校验元数据、相对链接及脚本，再在独立目录实际生成工程并运行测试。校验器成功不等于行为验证。

多个文件宜形成一个基于当前远端树的提交，用预期旧 SHA 更新分支，保留已有文件。远端移动时重新读取差异，不能强制覆盖；分支保护要求 PR 时采用已有流程，不顺带改变可见性、权限或部署设置。

发布后读取远端文件/树，比较清单和内容摘要，给可打开的目录或提交链接。上传失败则交付本地 skill 与准确错误，仅在真正阻塞时请求必要访问，不要求用户提供令牌。
